5. AWS STS ASSUMEROLE INTEGRATION (PHASE 3B.1)
-------------------------------------------------------------------------------
# Purpose: Ephemeral cross-account STS AssumeRole with CallerIdentity validation.
# No temporary credentials (AccessKeyId, SecretAccessKey, SessionToken) are ever
# stored in PostgreSQL or Redis. All temporary credentials exist in memory only.

# Manual Real AWS Connection Verification (Optional — requires active AWS credentials):
$env:AWS_ACCESS_KEY_ID="<your-cloudpilot-host-key>"
$env:AWS_SECRET_ACCESS_KEY="<your-cloudpilot-host-secret>"
$env:AWS_DEFAULT_REGION="us-east-1"

# Run standalone verification script against customer role:
py -c "
from app.providers.aws import AWSProvider
provider = AWSProvider(
    role_arn='arn:aws:iam::<TARGET_ACCOUNT_ID>:role/<ROLE_NAME>',
    external_id='<EXTERNAL_ID>',
    account_id='<TARGET_ACCOUNT_ID>',
    region='us-east-1'
)
print('Format valid:', provider.validate_role_arn_format())
identity = provider.verify_connection()
print('Verified Identity:', identity)
"

9. REDIS CACHING & CACHE INVALIDATION ARCHITECTURE (PHASE 3B.6)
-------------------------------------------------------------------------------
# Purpose: High-performance, fail-safe Redis caching for cloud resource summaries
# and listings with deterministic SHA-256 query hashing, strict workspace/account
# tenant isolation, post-commit cache eviction, and 100% graceful fallback to PostgreSQL.
#
# Key Features:
# - Connection pooling with connect/socket timeouts (2.0s), max pool size (20), & circuit breaker reconnect cooldown (5.0s)
# - Bounded TTLs: Summary (300s), Resource Listings (120s), Sync Status (30s)
# - Strict multi-tenant isolation: Keys partitioned by workspace_id and account_id
# - Versioned namespace: cloudpilot:v1:*
# - Versioned cache generations (cloudpilot:v1:gen:<ws_id>:<account_id>) eliminating concurrent read-after-invalidate race conditions
# - Fail-open resilience: Redis failures log warnings; APIs seamlessly fall back to DB
# - Security guarantee: Zero IAM Role ARNs, External IDs, or STS tokens in Redis
# - Authorization verified in PostgreSQL before any cache lookup
#
# Inspect Redis Cache Keys in Docker Container:
# docker compose exec redis redis-cli KEYS "cloudpilot:v1:*"
#
# Inspect Redis TTL for a cached key:
# docker compose exec redis redis-cli TTL "cloudpilot:v1:resources:summary:<ws_id>:<account_id>:0"
#
# Manually flush Redis test keys:
# docker compose exec redis redis-cli --scan --pattern "cloudpilot:v1:*" | xargs -r docker compose exec -T redis redis-cli DEL

10. DURABLE BACKGROUND SYNCHRONIZATION WORKER & JOB RECOVERY (PHASE 3B.7)
-------------------------------------------------------------------------------
# Purpose: High-reliability, independently running PostgreSQL-backed synchronization
# worker decoupled from the FastAPI API server process. Replaces in-memory background
# tasks with durable, multi-worker atomic job claiming, exponential backoff retries,
# and heartbeat-driven crash recovery.
#
# Key Features:
# - PostgreSQL authoritative job store with SELECT FOR UPDATE SKIP LOCKED
# - Zero external broker requirement (No Celery/RabbitMQ/Kafka needed)
# - Account-level concurrency lock: Prevents claiming overlapping jobs for active accounts
# - Exponential backoff retry engine for transient network/throttling failures
# - Heartbeat leases (120s): Automatically reclaims or fails dead worker jobs
# - Graceful shutdown: Listens to SIGTERM/SIGINT, finishes current job, cleans up sessions
# - Zero credential persistence: STS credentials strictly ephemeral
#
# Run Cloud Sync Worker standalone (Manual Python process):
cd backend/cloud-service
py -m app.workers.sync_worker

# Run Cloud Sync Worker via Docker Compose:
docker compose up -d cloud-sync-worker

# View live worker logs:
docker compose logs -f cloud-sync-worker

# Scale worker instances in Docker Compose:
docker compose up -d --scale cloud-sync-worker=3

# Stop or restart worker container:
docker compose restart cloud-sync-worker
docker compose stop cloud-sync-worker

# Run Phase 3B.7 tests specifically:
pytest backend/cloud-service/tests/test_sync_worker.py -v
